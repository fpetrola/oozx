## Cause

Dock was a bare list of names, so what each edge means in geometry lived in AttachedFrame as switches over it: where a
window rests against its machine (place), how far a window is from that resting place (distanceTo), which edge of
the window faces the machine's (facing), and where the glow line of an edge runs (edge), plus four copies of
`side == TOP || side == BOTTOM` for "runs along the width". Each switch wrote the same two facts per edge, whether it
runs along the width and whether it lies past the far border, in arithmetic of its own; FREE, which is no edge at
all, sat among them and every switch needed a default for it. Edge now owns the geometry of the four borders
(rest, line, laid, alongside, facing) from those two facts, and Dock says which edge it sits on, FREE on none.

## Principle

Polymorphism over type tests: when the same constants of an enum are decided over in several places, what is
decided is the constants' own behaviour, and belongs on them.

## Candidate rule

rule: enum-decided-outside
In one file, two or more places that decide over the same set of constants of one enum: switches whose case labels
are the same set of names, or disjunctions `x == E.A || x == E.B` naming the same constants. One finding per
(enum, set of constants), at the first place. It would have caught the four switches over BOTTOM, TOP, LEFT, RIGHT in
the old machine/ui/src/main/java/com/fpetrola/oozx/speccy/windows/AttachedFrame.java:355 and the repeated `side == Dock.TOP || side == Dock.BOTTOM`.
